# 🧠 Ultimate Viva Question Bank

This is your cheat sheet for the theory part of the viva. Read these questions and answers to understand the "why" behind the code.

## 🟢 Vue.js & Frontend

**Q: What is the difference between `v-bind` and `v-model`?**
**A:** `v-bind` (or just `:`) is **One-Way Data Binding**. It takes data from JavaScript and pushes it into an HTML attribute (like `:disabled="true"`). `v-model` is **Two-Way Data Binding**. It links an input field (like a text box) to a JS variable. If the user types, the JS updates. If the JS updates, the input box updates.

**Q: Why do we use `ref()` in Vue 3?**
**A:** `ref()` makes a variable **reactive**. Normally, if a JavaScript variable changes, the HTML doesn't care. But if a variable is wrapped in `ref()`, Vue constantly watches it. The moment it changes, Vue automatically re-renders the specific HTML that uses that variable.

**Q: What is the Virtual DOM?**
**A:** Updating the actual browser DOM (HTML) is very slow. Vue keeps a lightweight "virtual" copy of the DOM in memory. When a reactive variable changes, Vue updates the Virtual DOM, compares it to the real DOM, and only applies the exact, specific changes needed. This makes it incredibly fast.

**Q: Why do you need `:key` in a `v-for` loop?**
**A:** The `:key` gives a unique ID to every element generated by a loop. When the array changes (e.g., a trek is deleted), Vue uses the key to quickly find which exact element to remove from the DOM without having to re-draw the entire list.

## 🔵 Flask & Python Backend

**Q: Explain the Application Factory pattern in Flask.**
**A:** Instead of creating the `app = Flask(__name__)` globally at the top of the file, the Application Factory pattern creates the app inside a function (or delays attaching extensions like `db.init_app(app)`). This prevents "circular imports" where two Python files try to import each other and crash.

**Q: What is CORS and why did you use `CORS(app)`?**
**A:** CORS stands for Cross-Origin Resource Sharing. It's a browser security feature. By default, a frontend running on `localhost:8080` (or purely in HTML) is not allowed to make fetch requests to a backend running on `localhost:5000`. `CORS(app)` tells the backend to accept requests from any origin.

**Q: How does JWT Authentication work in your app?**
**A:** 
1. The user logs in with username/password.
2. The server verifies it and generates a JWT (JSON Web Token), signing it with a `JWT_SECRET_KEY`.
3. The server sends the token to the frontend, which stores it in `localStorage`.
4. For every future request to a protected route, the frontend sends the token in the HTTP Header `Authorization: Bearer <token>`.
5. The backend (`@jwt_required()`) decodes the token mathematically to verify the user without needing to look up the database again.

## 🟠 Database & SQLAlchemy

**Q: What is an ORM?**
**A:** ORM stands for Object-Relational Mapper. SQLAlchemy is an ORM. It translates Python classes into database tables, and Python objects into rows. It prevents us from having to write raw SQL strings (like `SELECT * FROM user`), which prevents SQL Injection attacks and makes code easier to write.

**Q: Explain `lazy=True` in `db.relationship()`.**
**A:** If we load a `User`, we don't necessarily want to load all 1,000 of their bookings instantly (that would be slow). `lazy=True` means SQLAlchemy will not query the `bookings` table until we actually type `user.bookings` in our code.

## 🟣 Celery & Background Tasks

**Q: What is Celery and why do you need it?**
**A:** Celery is an asynchronous task queue. If a user clicks "Export CSV", and the database has 1 million rows, generating the CSV might take 10 seconds. If we did it normally in Flask, the user's browser would freeze for 10 seconds waiting for a response. Instead, Flask hands the job to Celery to do in the background and immediately tells the user "Export started!".

**Q: Why do you need `celery beat`?**
**A:** The Celery *Worker* executes tasks. `celery beat` is the scheduler. It acts like an alarm clock. When the alarm goes off (e.g., every day at midnight), `beat` takes a task and puts it in the queue for the *worker* to execute.

## 🔴 Redis

**Q: What are the two roles Redis plays in your app?**
**A:**
1. **Message Broker:** It acts as the post office between Flask and Celery. Flask puts a "task" into Redis. Celery reads the "task" from Redis and does it.
2. **Cache:** We temporarily store the expensive output of `get_treks()` inside Redis as a string for 60 seconds (`redis_client.set`). For the next 60 seconds, anyone asking for treks gets the instant Redis string instead of forcing the SQLite database to search its tables.
